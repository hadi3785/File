# ربات فشرده‌ساز و استخراج (ZIP / RAR)

- چند فایل بفرست ← فرمت (ZIP یا RAR)، رمز و اسم را انتخاب کن ← یک آرشیو تحویل بگیر
- فایل ZIP / RAR / 7z / TAR بفرست ← محتویاتش تک‌تک برمی‌گردد؛ اگر رمز داشته باشد، ربات رمز را می‌پرسد
- تا حدود ۲ گیگابایت (با Telethon/MTProto)

## دیپلوی روی Railway

1. فایل‌های `bot.py`, `db.py`, `storage.py`, `Dockerfile`, `requirements.txt` را در یک ریپوی GitHub بگذار و در Railway گزینه **Deploy from GitHub repo** را بزن.
2. متغیرهای `API_ID`, `API_HASH` (از my.telegram.org) و `BOT_TOKEN` (از BotFather) را اضافه کن.

### برای حل مشکل دیسک: Volume

دیتابیس جای فایل‌ها را نمی‌گیرد؛ راه‌حل واقعی برای فضای دیسک **Volume** است:

1. روی سرویس ربات: **Add → Volume** و Mount Path را `/data` بگذار.
2. متغیر `WORK_DIR=/data/work` را اضافه کن (اگر `/data` وجود داشته باشد، خودکار همین‌جا کار می‌کند).
3. حجم Volume به پلن Railway بستگی دارد؛ از تنظیمات خود Volume می‌توانی ببینی/زیادش کنی.

ربات خودش هم مراقب دیسک است: قبل از دریافت هر فایل فضای خالی را چک می‌کند، فایل‌ها را بلافاصله بعد از ارسال پاک می‌کند، حجم استخراج را حین کار زیر نظر دارد (ضد زیپ‌بمب) و در شروع هر اجرا پوشه‌ی موقت را تمیز می‌کند.

### Bucket (لینک دانلود برای همه‌ی خروجی‌ها)

با Bucket، هر آرشیو ساخته‌شده و هر فایل استخراج‌شده در Bucket آپلود می‌شود و ربات یک **لینک دانلود موقت** می‌فرستد (دکمه‌ی «⬇️ دانلود»). به این ترتیب خروجی بالای ۲ گیگ هم مشکلی ندارد و فایل بعد از آپلود فوراً از دیسک پاک می‌شود.

1. در پروژه: **New → Bucket**.
2. در سرویس ربات این متغیرها را بساز و مقدارشان را با Variable Reference از Bucket بگیر (از تب Credentials/Variables خود Bucket):

| متغیر ربات | مقدار از Bucket |
|---|---|
| `S3_ENDPOINT` | Endpoint (مثلاً `https://storage.railway.app`) |
| `S3_BUCKET` | نام Bucket |
| `S3_ACCESS_KEY_ID` | Access Key ID |
| `S3_SECRET_ACCESS_KEY` | Secret Access Key |
| `S3_REGION` | Region (اگر نبود، `auto`) |

3. اگر Bucket قدیمی است و خطای آدرس می‌دهد، `S3_ADDRESSING=path` را اضافه کن.
4. `LINK_TTL_HOURS` (پیش‌فرض 24، حداکثر 168) مدت اعتبار لینک است. ربات هر ۱۵ دقیقه فایل‌های منقضی را از Bucket پاک می‌کند، پس هزینه جمع نمی‌شود.
5. اگر می‌خواهی علاوه بر لینک، خود آرشیو (تا ۲ گیگ) در چت هم بیاید: `SEND_IN_TELEGRAM=1`.

اگر `S3_*` تنظیم نباشد، ربات مثل قبل مستقیم در تلگرام می‌فرستد.

> **هزینه:** طبق مستندات Railway، عملیات S3 و دانلود از Bucket رایگان است، ولی آپلود از سرویس ربات به Bucket روی شبکه‌ی عمومی انجام می‌شود و به‌عنوان egress سرویس طبق نرخ استاندارد حساب می‌شود. ذخیره‌سازی هم به‌ازای هر گیگ در ماه محاسبه می‌شود. Bucket در Limited Trial در دسترس نیست.
> **حریم خصوصی:** هر کسی لینک را داشته باشد تا انقضا می‌تواند فایل را دانلود کند؛ لینک را به اشتراک نگذار.

### دیتابیس (اختیاری)

1. در پروژه: **New → Database → PostgreSQL**.
2. در سرویس ربات یک متغیر `DATABASE_URL` بساز و مقدارش را با Reference به `DATABASE_URL` دیتابیس بگذار.
3. جدول‌ها خودکار ساخته می‌شوند. دیتابیس این‌ها را نگه می‌دارد: کاربران، فرمت پیش‌فرض هر کاربر (ZIP/RAR)، لاگ کارها، آمار (`/stats`) و سهمیه روزانه.

اگر `DATABASE_URL` نباشد، ربات بدون دیتابیس هم کامل کار می‌کند.

## متغیرهای اختیاری

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `WORK_DIR` | `/data/work` یا `/tmp/archive-bot` | پوشه‌ی کاری موقت |
| `ALLOWED_USERS` | خالی | آیدی عددی کاربران مجاز، با کاما (خالی = همه) |
| `MAX_FILE_MB` | 1500 | حداکثر حجم هر فایل ورودی |
| `MAX_TOTAL_MB` | 1800 | حداکثر مجموع حجم برای ساخت آرشیو |
| `MAX_EXTRACT_MB` | 3000 | حداکثر حجم بعد از استخراج |
| `MAX_SEND_FILES` | 50 | حداکثر تعداد فایل ارسالی بعد از استخراج |
| `RESERVE_MB` | 300 | فضای خالی که همیشه نگه داشته می‌شود |
| `MAX_PARALLEL_JOBS` | 2 | تعداد کار همزمان (کنترل مصرف دیسک و CPU) |
| `DAILY_LIMIT_MB` | 0 | سهمیه روزانه هر کاربر؛ 0 = نامحدود (نیاز به دیتابیس) |
| `SESSION_TTL_MIN` | 60 | پاک‌سازی خودکار نشست‌های بی‌استفاده |
| `LINK_TTL_HOURS` | 24 | اعتبار لینک دانلود (فقط با Bucket) |
| `SEND_IN_TELEGRAM` | 0 | با 1، فایل آرشیو علاوه بر لینک در چت هم ارسال می‌شود |

## نکته‌ها

- **RAR**: ساخت RAR با برنامه‌ی رسمی `rar` انجام می‌شود که شیر‌ور (trial/پولی) است؛ برای استفاده‌ی شخصی مشکلی نیست، ولی برای استفاده‌ی تجاری لایسنس لازم است. در لاگ شروع، مقدار `rar=True/False` را ببین؛ اگر `False` بود، دکمه‌ی RAR نمایش داده نمی‌شود.
- **ZIP رمزدار** با AES-256 ساخته می‌شود (با 7-Zip و WinRAR باز می‌شود؛ مدیر فایل پیش‌فرض ویندوز آن را باز نمی‌کند).
- **RAR رمزدار** نام فایل‌ها را هم رمز می‌کند.
- آرشیوهای چندتکه‌ای (part1.rar, part2.rar ...) فعلاً پشتیبانی نمی‌شوند.
